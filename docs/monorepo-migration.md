# 合并与升级说明

源码基准：PicPeak `c388c125`，Bridge `0746de8`。Bridge 通过 Git subtree 导入 `bridge/`，保留来源导入记录和 LICENSE。由于旧 PicPeak 仓库部分旧历史对象缺失，新工作区保留完整的当前提交源码和该提交标识，以浅历史开始；旧仓库没有被覆盖。以后如需查阅更早历史，应先恢复旧仓库的缺失对象，不能假定新仓库已有完整旧历史。

根目录为唯一构建上下文，统一 Dockerfile 同时构建前端、后台和 Bridge。运行时 PicPeak 监听 3000；Bridge 只监听容器内 127.0.0.1:8080。两个服务保持独立数据库与权限，原 RAW 根目录只读。

已有安装必须保留 `/data` 与 `/bridge-data`，包含数据库、配置、布局迁移记录和处理任务。更新前停止旧容器并备份两个数据卷，确认 Compose 指向既有卷。禁止把空卷误当作升级后的数据卷。

旧 `event-ID-name` 交付目录会迁移到项目专属挂载根。迁移先持久化路径映射，数据库路径在 Bridge 启动时按记录重新映射；中途重启仍可重复执行。发现新旧目录都有数据时停止处理，需人工确认，不能覆盖。

数据库迁移新增撤回任务与阶段意图表。离线时任务持久保存，连接恢复后重试。未知上传结果只核对文件标记，不盲目重复写入；无法确认的撤回会停在异常状态，摄影师应核对原片与 NAS 目录。旧审核中的返修需求迁移为 open，之后移除审核界面与分支。

本版本仅支持向前升级。旧镜像不理解新增处理任务，回退应恢复升级前的一致性备份，而非只替换镜像。项目删除不会去删除 Camera 的原始照片。

本仓库自行维护，不自动合并官方上游。CI 覆盖 dev/main 的前后端测试、中文键检查、Bridge 测试、统一镜像和真实容器验证；发布由 main 上手动操作触发，使用固定版本标签。
