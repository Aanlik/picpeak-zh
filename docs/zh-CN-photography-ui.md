# 中文摄影界面与精修状态

本配置以 NO_EMAIL_MODE/VITE_NO_EMAIL_MODE 为开关，保留官方完整界面的恢复路径。

- 新建项目只显示“项目基本信息”、项目名称和拍摄日期；拍摄类型、全天/时段及欢迎留言均已从界面移除。旧数据库中的类型字段仅按固定默认值兼容，不提供类型配置或筛选。
- 项目概览隐藏品牌短 URL，保留原始客户分享链接。
- 客户选片、登录、过期页和不存在的相册页隐藏法律/隐私占位链接。官方模式中实际 CMS 页仍按原设置显示；没有 CMS 页时不凭空生成链接。
- 中文“画廊”统一为“相册”，“事件”统一为“项目”，“主办方/组织者”改为“摄影师”；原 key 和插值变量不变。
- 项目概览增加“选片与精修进度”，在 PicPeak 后台查看照片、项目阶段、客户需求和同步异常；支持回滚阶段、立即同步、重扫和重试。
- 需求卡片显示照片缩略图、原始文件名、照片编号、客户说明、历史状态和导出目录，不必切换到 Bridge 工作台处理日常流程。
- 客户可按待选片、已选择、精修中、已交付、待处理需求和已撤回快速筛选照片；批量选片控件保留。
- 客户可以撤回未完成的返修/新增需求，也可以撤回已交付照片的后续精修选择。已交付成片留在相册，RAW 与历史版本保留，Bridge 停止后续自动上传。
- 首次精修导出到 `04_FINAL/V1`；客户为已交付照片提交新的需求时，自动创建下一版本目录（`V2`、`V3`……），并在 PicPeak 需求卡片中显示准确路径。
- 浏览器预览 URL 加入当前成片版本号作为缓存键；客户工作流状态每 15 秒刷新，因此同一设备也会重新请求最新预览。

## 状态来源与边界

业务状态保存在独立 Bridge，PicPeak 仅通过管理员认证、events.view 权限和项目所有权检查的内部代理读取。Bridge 密码不发送给浏览器；Bridge 不对外开放。未关联项目会明确显示尚未关联，不显示虚假的零进度。

PicPeak 服务配置：

```
PIXCAKE_BRIDGE_URL=http://bridge:8080
PIXCAKE_BRIDGE_PASSWORD=<与 BRIDGE_ADMIN_PASSWORD 相同>
```

追加选片：项目已有完整同步记录，进入 EDITING 或 DELIVERED 后，客户从未选变为绿色选择。以照片计数，再次轮询不会重复累加；客户取消后从当前追加数量中扣除。该记录持久保存，重启不丢失。

升级不会凭空重建历史：旧数据库增加 added_during_editing 列并默认 false，过去缺少时间线的追加无法准确反推。后续变化从升级后记录。

返修：Bridge 只扫描每张照片当前待交付的 `Vn` 目录，并按 `source_filename` 匹配原片。相同内容的 SHA-256 不重复上传；新内容会替换同一个 PicPeak 照片，保留照片 ID、评论、评分、颜色标记、排序和分享链接。失败和待上传任务不计入成功版本数。

撤回保护：在项目仍处于首次选片阶段、且从未进入后期时，取消标记可清理 Bridge 创建的待精修副本。项目进入过后期后，即使摄影师把阶段回滚到“客户选片”，撤回也不会删除可能正在软件中处理的 RAW。已交付成片与历史快照始终保留。

常规操作直接在 PicPeak 的项目管理卡片完成。Bridge 仍是独立的内部同步服务，负责轮询客户绿色标记、只读匹配 NAS RAW、监听版本目录、生成历史快照及调用 PicPeak 替换接口；客户浏览器不直接访问 Bridge。
