# 本地账号与链接分享模式

中文版摄影工作流部署默认开启此模式：前端构建参数 `VITE_NO_EMAIL_MODE=true`，AIO 服务端环境 `NO_EMAIL_MODE=true`。两侧必须配套。该模式以用户名和密码管理摄影师账号，以 PicPeak 分享链接交付给客户，不接入短信、微信或其他消息 API。

管理员首次初始化填写用户名，不需要邮箱；现有账号可通过管理员资料接口修改 username，密码、用户 ID、权限及照片数据保留。本机已将原账号改为 `admin`，密码仍在 NAS 的私有登录说明文件中。不要把凭证提交到仓库。

客户选片使用匿名设备身份或共享颜色模式，不填写邮箱；新建画廊不要求客户/摄影师邮箱。发布后复制链接，通过摄影师自己的微信等渠道发送。评分、评论、收藏和精修标记照常工作。

邮件设置、SMTP、通知发送、邮件邀请与恢复入口关闭。后台新增本地账号管理页，只有超级管理员可创建账号并分配角色，初始密码满足安全要求，首次登录强制修改密码。不通过邮件交付或找回密码。摄影师忘记密码时需要由部署负责人在私有 NAS 管理通道执行恢复，未新增任何公开免验证的密码恢复端点。

官方的邮件依赖模块（邮件收发、newsletter、邮件提醒、客户邮箱登录门户、合同/报价/发票的邮件交付及 PicTransfer）在该部署模式下不启用。它们的源码和历史记录保留，上游兼容模式仍可使用。不能把隐藏邮件登录入口当成用其他方式实现了合同身份验证；此模式没有绕过邮件验证码访问合同或报价数据。

现有数据库里的 email 字段仅为上游兼容保留，不做破坏性删除。新建本地账号使用保留域名 `accounts.invalid` 的内部占位值，由服务生成，用户无需填写，邮件服务不会处理这些值。邮件发送、队列消费和 IMAP 轮询在服务端关闭；旧队列保留，回到上游邮件模式前务必核对待发送项。

## 上游维护

修改集中于 communication 配置/服务端策略、本地账号路由、登录初始化及少量界面分支。原有分支保留，默认单元测试仍使用上游模式；CI 额外检查本地模式。不要删除 en/zh-CN 里的邮件翻译键，否则会破坏 parity 并增加上游冲突。

若要恢复官方行为，需要以 `VITE_NO_EMAIL_MODE=false` 重建前端/AIO，并设置 `NO_EMAIL_MODE=false` 后重建容器；单独改运行环境不会改变已构建的界面。

## 验证

前端完整 883 个测试、3 个本地模式专门测试；5 个独立服务端策略测试。真实容器核验用户名初始化、拒绝邮箱登录、本地账号创建、重复/非法用户名及弱密码拒绝、未登录/非超级管理员权限拒绝、关闭邮件 API 与邮箱必填规则。真实 PicPeak + Bridge 100 张选片/精修/返修/重启闭环保持通过，原始 RAW SHA256、照片 ID、反馈与分享链接保持不变。
