## A01 / P1：回滚失败后仍删除恢复前的安全备份

位置：backend/src/services/restoreService.js:757；安全备份创建位置为同文件 createPreRestoreBackup。

安全备份保存于 this.tempDir/pre-restore-*。恢复失败且安全回滚失败时，虽然 Bridge 已保持暂停，finally 仍无条件递归删除整个 this.tempDir。恢复前数据库备份和文件备份随之消失，管理员无法使用报告中的路径人工重试回滚。项目若已被部分恢复，缺少这份安全备份可能造成无法恢复的数据损失。

复现：使用真实 RestoreService，建立包含模拟原数据库备份文件的安全备份目录，注入恢复失败及回滚失败；确认持久化暂停被调用，但返回后安全备份目录已不存在。故障注入测试通过。此复现没有损坏真实 NAS 数据库，也没有执行生产数据库导入。

建议：将安全备份放入独立的持久化恢复目录；恢复或回滚不完整时保留目录并在记录中保存可访问路径。临时下载和解压文件单独清理。覆盖恢复失败、回滚失败、成功恢复后的保留策略及人工重试测试。

## A02 / P1：执行中的恢复暂停在 Bridge 重启后丢失

位置：bridge/src/pixcake_bridge/engine.py:21；bridge/src/pixcake_bridge/app.py:54、363。

普通 checkpoint 的 token 和 maintenance_until 只存在内存。启动时仅恢复发生失败后写入的 restore-block.json，并不恢复仍在执行的备份/恢复检查点。如果 Bridge 在 PicPeak 正在替换数据库或复制文件时重启，自动同步会恢复，旧恢复任务也无法续期或持久化失败暂停；两侧可能在恢复期间发生写入和进度分歧。

复现：创建真实 FastAPI 检查点后，同步接口返回 503；关闭并重建应用、重新打开同一 SQLite 后，同步接口变成 200。旧 token 续期及 block 请求均返回 409。使用相同配置及数据库的应用生命周期重启测试，未执行 NAS 重启。

建议：持久化执行中的检查点及任务身份。恢复任务重启后必须保持暂停，待共同恢复/回滚确认或管理员核对后解除；普通备份是否允许租约到期应采用明确的单独策略。加入备份途中、数据库恢复途中和文件复制途中 Bridge 重启的联合回归测试。

## A03 / P2：请求超时后检查点仍被创建，导致无人持有的暂停

位置：backend/src/services/photographyWorkflowBridge.js:3、24；bridge/src/pixcake_bridge/app.py:354–365。

PicPeak 到 Bridge 的请求统一在 5 秒超时，检查点却可能长时间等待正在同步/上传的 engine.lock。调用方超时退出后，服务端仍可能继续运行并创建检查点。PicPeak 已报告备份停止，没有拿到 token，也没有启动续期或释放流程；Bridge 因此暂停约 30 分钟。RAW 扫描或上传耗时较长时可触发。

复现：启动真实 Uvicorn HTTP 服务，让 engine.lock 占用 5.5 秒；客户端以 5 秒超时请求检查点并断开。随后确认服务端仍创建 token，同步接口返回 503，剩余暂停时间约 1800 秒。这里测试的客户端为 httpx，超时长度与 PicPeak 的配置相同。

建议：使用调用方生成的幂等任务 ID，让调用方可在超时后查询或取消自己的检查点；锁等待采用明确的超时/忙碌响应，提交租约前检查请求仍有效。单纯增大 HTTP 超时不能完整处理断网后的未知结果。加入慢同步、超时和断开连接回归测试。
